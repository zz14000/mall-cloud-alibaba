# 本项目动态权限实现完整解析

## 一、核心设计理念

本项目采用 **RBAC（Role-Based Access Control）基于角色的访问控制** 模型，实现了两套权限体系：

```
┌─────────────────────────────────────────────────────────┐
│                    权限体系统一框架                       │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  📋 菜单权限（Menu）          🔐 资源权限（Resource）     │
│  ──────────────────          ───────────────────        │
│  • 控制前端页面展示           • 控制后端 API 访问          │
│  • 树形结构组织               • URL 路径匹配              │
│  • 目录/菜单/按钮三级          • 按功能模块分类            │
│  • 角色分配菜单               • 角色分配资源              │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

#### 步骤 4：后端加载用户信息和权限

**源码位置**：`mall-cloud-alibaba/.../service/impl/UmsAdminServiceImpl.java#L118-L138`

```java
@Override
public String login(String username, String password) {
  String token = null;
  try {
    // ① 调用 loadUserByUsername 加载用户信息和权限
    UserDetails userDetails = loadUserByUsername(username);
    
    // ② 验证密码
    if (!passwordEncoder.matches(password, userDetails.getPassword())) {
      throw new BadCredentialsException("密码不正确");
    }
    
    // ③ 构建认证令牌（包含用户权限）
    UsernamePasswordAuthenticationToken authentication = 
      new UsernamePasswordAuthenticationToken(
        userDetails, null, userDetails.getAuthorities());
    
    // ④ 放入安全上下文，后续请求可获取当前用户信息
    SecurityContextHolder.getContext().setAuthentication(authentication);
    
    // ⑤ 生成 JWT Token（包含用户名和过期时间）
    token = jwtTokenUtil.generateToken(userDetails);
    
    // ⑥ 将 token 存入 Redis，支持服务端主动失效
    adminCacheService.setToken(username, tokenHead + token);
    
    // ⑦ 记录登录日志
    insertLoginLog(username);
  } catch (AuthenticationException e) {
    LOGGER.warn("登录异常:{}", e.getMessage());
  }
  return token;
}
```

#### 步骤 5：加载用户权限详情（loadUserByUsername）

**源码位置**：`mall-cloud-alibaba/.../service/impl/UmsAdminServiceImpl.java#L331-L340`

```java
@Override
public UserDetails loadUserByUsername(String username) {
  // ① 从数据库获取用户信息（带缓存）
  UmsAdmin admin = getAdminByUsername(username);
  if (admin != null) {
    // ② 查询该用户通过角色关联的所有 API 资源权限
    List<UmsResource> resourceList = getResourceList(admin.getId());
    
    // ③ 封装成 UserDetails，resourceList 会被转为 GrantedAuthority
    return new AdminUserDetails(admin, resourceList);
  }
  throw new UsernameNotFoundException("用户名或密码错误");
}

// getResourceList 实现（带 Redis 缓存）
@Override
public List<UmsResource> getResourceList(Long adminId) {
  String key = REDIS_DATABASE + ":" + REDIS_KEY_RESOURCE_LIST + ":" + adminId;
  List<UmsResource> resourceList = (List<UmsResource>) redisService.get(key);
  if (resourceList != null) {
    return resourceList;  // 缓存命中直接返回
  }
  // 缓存未命中，从数据库查询
  resourceList = adminRoleRelationDao.getResourceList(adminId);
  if (resourceList != null) {
    redisService.set(key, resourceList, REDIS_EXPIRE);
  }
  return resourceList;
}
```

#### 步骤 7：生成 JWT Token

**源码位置**：`mall-cloud-alibaba/.../security/util/JwtTokenUtil.java#L44-L50`

```java
private String generateToken(Map<String, Object> claims) {
  return Jwts.builder()
    .setClaims(claims)  // 包含用户名、创建时间等
    .setExpiration(generateExpirationDate())  // 设置过期时间
    .signWith(SignatureAlgorithm.HS512, secret)  // 签名
    .compact();
}
```

**Token 格式**：`header.payload.signature`

**Payload 示例**：
```json
{
  "sub": "admin",  // 用户名
  "created": 1489079981393,  // 创建时间
  "exp": 1489684781  // 过期时间
}
```

```javascript
actions: {
  Login({ commit }, userInfo) {
    const username = userInfo.username.trim();
    return new Promise((resolve, reject) => {
      login(username, userInfo.password).then(response => {
        const data = response.data;
        const tokenStr = data.tokenHead + data.token;

        commit('SET_TOKEN', tokenStr);
        resolve();
      }).catch(error => {
        reject(error);
      });
    });
  }
}
```

```javascript
          });

      }
    }
  } else {

      next();

      NProgress.done();
```

```javascript
actions: {
  GenerateRoutes({ commit }, data) {
    return new Promise(resolve => {
      const { menus } = data;
      const { username } = data;
      // 过滤 asyncRouterMap，只保留用户有权限的路由
      const accessedRouters = asyncRouterMap.filter(v => {
        if (hasPermission(menus, v)) {
          if (v.children && v.children.length > 0) {
            v.children = v.children.filter(child => {
              if (hasPermission(menus, child)) {
                return child;
              }
              return false;
            });
            return v;
          } else {
            return v;
          }
        }
        return false;
      });
      // 对菜单进行排序
      sortRouters(accessedRouters);
      commit('SET_ROUTERS', accessedRouters);  // 提交路由
      resolve();
    });
  }
}
```

```javascript
function hasPermission(menus, route) {
  if (route.name) {
    let currMenu = getMenu(route.name, menus);
    if (currMenu != null) {
      route.meta.title = currMenu.title;  // 设置标题
      route.meta.icon = currMenu.icon;    // 设置图标
      route.hidden = currMenu.hidden !== 0; // 设置可见性
      route.sort = currMenu.sort;         // 设置排序
      return true;
    } else {
      route.sort = 0;
      if (route.hidden !== undefined && route.hidden === true) {
        return true;
      } else {
        return false;  // 无权限，隐藏该路由
      }
    }
  } else {
    return true;
  }
}
```

```java
@Override
public void decide(Authentication authentication, Object object,
                   Collection<ConfigAttribute> configAttributes) {
    if (CollUtil.isEmpty(configAttributes)) {
        return; // 未配置权限的接口直接放行
    }
    
    Iterator<ConfigAttribute> iterator = configAttributes.iterator();
    while (iterator.hasNext()) {
        ConfigAttribute configAttribute = iterator.next();
        String needAuthority = configAttribute.getAttribute();
        
        for (GrantedAuthority grantedAuthority : authentication.getAuthorities()) {
            if (needAuthority.trim().equals(grantedAuthority.getAuthority())) {
                return; // 匹配成功，放行
            }
        }
    }
    throw new AccessDeniedException("抱歉，您没有访问权限");
}
```

| 特性 | 实现方式 | 优势 |
|------|---------|------|
| **动态菜单** | 基于用户角色过滤路由表 | 不同角色看到不同菜单 |
| **动态 API 权限** | URL 匹配 + 权限决策器 | 细粒度接口访问控制 |
| **Redis 缓存** | 缓存用户权限列表 | 减少数据库查询，提升性能 |
| **懒加载策略** | 删除缓存而非更新 | 简化实现，避免并发问题 |
| **JWT 无状态** | Token 携带用户信息 | 支持分布式部署 |
| **缓存失效** | 权限变更时删除缓存 | 保证最终一致性 |

## 七、为什么选择删除缓存而不是更新缓存？

### 1. 避免并发一致性问题

**更新缓存的风险：**
```
时间线：
T1: 线程 1 更新数据库：权限 = [资源 1, 资源 3] ✅
T2: 线程 1 准备更新缓存
T3: 线程 2 读取旧缓存：权限 = [资源 1, 资源 2] ❌
T4: 线程 1 更新缓存：权限 = [资源 1, 资源 3]
T5: 线程 2 基于旧缓存执行业务逻辑 ❌ 数据不一致！
```

**删除缓存的优势：**
```
时间线：
T1: 线程 1 更新数据库：权限 = [资源 1, 资源 3] ✅
T2: 线程 1 删除缓存 ✅
T3: 线程 2 发现缓存不存在，重新从数据库加载 ✅
T4: 线程 2 获取最新权限：[资源 1, 资源 3] ✅ 数据一致！
```

### 2. 简化实现复杂度

**更新缓存（复杂）：**
- 需要立即查询所有受影响用户的最新权限
- 需要处理更新失败的回滚逻辑
- 需要保证数据库和缓存的原子性更新

**删除缓存（简单）：**
- 直接删除 Redis 键即可
- 下次请求时自动加载最新数据
- 无需处理并发问题

### 3. 性能优势

```
假设给角色分配了 100 个资源，该角色下有 50 个用户

更新缓存策略：
- 需要立即查询 50 次数据库（每个用户查一次最新权限）
- 需要更新 50 个 Redis 键
- 即使用户短期内不登录，也会执行这些操作（浪费）

删除缓存策略：
- 直接删除 50 个 Redis 键（1 次批量操作）
- 用户下次登录时才查询数据库
- 如果用户 1 小时后登录，这 1 小时内节省了数据库查询
```

### 4. 容错性更好

**更新缓存：** 更新失败会导致数据库和缓存永久不一致

**删除缓存：** 即使删除失败，缓存有过期时间，最终会一致
